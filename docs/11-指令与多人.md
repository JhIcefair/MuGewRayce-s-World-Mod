# §11 指令与多人

## §11.1 指令总表

`/mugewrayce` 是唯一的根指令，下面挂四组：`size`（体型）、`entity`（角色）、`itemgive`（发放物品）、`summon`（召唤实体）。

| 语法 | 作用 | 谁能用 |
|---|---|---|
| `/mugewrayce size adjust <身高cm> [目标玩家]` | 应用身高并联动属性；身高只能填 10~1000 | 能执行指令的人 |
| `/mugewrayce size reset [目标玩家]` | 恢复默认尺寸 | 能执行指令的人 |
| `/mugewrayce size special [目标玩家]` | 应用 icefair 特殊尺寸组 | 能执行指令的人 |
| `/mugewrayce size status [目标玩家]` | 显示当前全部属性值 | 能执行指令的人 |
| `/mugewrayce entity default [目标玩家]` | 角色切换：默认（完全没有任何变化） | 能执行指令的人 |
| `/mugewrayce entity magic [目标玩家]` | 角色切换：有生命的魔法体（物理免疫） | 能执行指令的人 |
| `/mugewrayce entity special <特殊角色> [目标玩家]` | 角色切换：特殊；字段目前只能填 `icefair`，输入时有补全 | 能执行指令的人 |
| `/mugewrayce itemgive <id> [数量] [目标玩家]` | 发放**本模组**物品；数量 1~64，不填为 1 | 需要管理员权限，与 `/give` 同级 |
| `/mugewrayce summon lifeless_magic_body [数量] [目标玩家]` | 在目标脚下召唤**没有生命的魔法体**；数量 1~16，不填为 1 | 需要管理员权限，与 `/itemgive` 同级 |

- `size` 与 `entity` 没有额外的权限门槛：能敲指令就能用；单人游戏要先在创建世界时允许作弊。
- `[目标玩家]` 省略时作用在自己身上，填了就对那个玩家生效——`size` 与 `entity` 两组都能直接改别人。
- `<id>` **只接受本模组物品**：可以写全名（`mugewrayce-mod:magic_staff`），也可以只写短名（`magic_staff`）；输入时的补全列表也只有本模组物品，原版物品请用 `/give`。
- 没有查看或设置区块魔力的指令：`/mugewrayce mana` 这一类本版不存在，看魔力请用魔力值探测器（见 §6.2）。

## §11.2 常用示例

**换成有生命的魔法体** —— `/mugewrayce entity magic`，聊天栏回「已切换角色：有生命的魔法体」。切回原样用 `/mugewrayce entity default`。

**变成 icefair** —— `/mugewrayce entity special icefair`，回「已切换角色：特殊-icefair」。字段写错会提示「未知特殊角色」，并列出当前可选的字段。

**改身高** —— `/mugewrayce size adjust 165`，回「身高已调整为 165 cm」。填 5 或 1200 都会回「身高必须在 10 到 1000 之间」，且不生效。

**查当前属性** —— `/mugewrayce size status`，一次输出整块状态（身高、移动速度、跳跃强度、生命值等）。加名字可以看别人：`/mugewrayce size status Alex`。

**考完把体型重置** —— `/mugewrayce size reset`，回「已恢复默认尺寸」。icefair 特殊尺寸也用这一条退出。

**给朋友一套法杖** —— `/mugewrayce itemgive magic_staff 1 Alex`，物品直接进对方背包；背包塞不下就掉在他脚下。

**自己领一张考试申请书** —— `/mugewrayce itemgive beginner_magic_exam_application`。拿得到，但这样拿到的是没有目标信息的空申请书，属于无效物品（见 §1.5）。

**服务端一次发多个** —— `/mugewrayce itemgive magic_crystal 8`，数量上限 64；要更多就分几次发。

**召唤几个魔法体** —— `/mugewrayce summon lifeless_magic_body 3`，脚下出现 3 个没有生命的魔法体；`... 3 Alex` 则召到 Alex 脚下。

## §11.3 多人边界

- **区块魔力按区块、按维度隔离。** 同一区块里的所有玩家共用一本账；下界、末地与主世界坐标会重名，但各记各的（见 §6.1）。
- **同时施法的扣魔顺序。** 一次施法当场结算，不排队也不预留：从所在区块起按位置判定依次扣，同一区块里先结算的那次先扣，后结算的那次余额不足就直接失败并提示「魔力不足」。
- **考试各自独立。** 谁右键申请书谁就是发起者；别人可以帮忙打目标，替你打完也算你通过，但只有发起者收到提醒。两场考试范围重叠时，目标按发起者的 UUID 区分归属（见 §5.9）。
- **HUD 只给发起者。** 屏幕上那两行（信息 + 倒计时）只有发起者看得见；奖励箱正上方那行世界文字所有人都能看到（见 §5.9）。
- **奖励箱。** 谁都能打开箱子拿走奖励，包括抢走通过证明；但只有发起者能拆，别人拆不掉。考试结束后箱子不再受保护，变成普通箱子。
- **防爆。** 模组里一切会破坏方块的效果——归零破块、魔法球命中方块的爆炸、群体伤害魔法阵——都受原版规则 `mobGriefing` 约束：把防爆打开（`mobGriefing=false`）后就不再破块。基岩这类硬度 -1 的方块任何情况下都不破。
- **时间暂停不冻玩家，也不影响昼夜。** 只冻结受影响区域内的实体与方块事件——TNT、落沙、矿车、掉落物的消失计时、活塞等方块事件、雷暴与区域刷怪都停；**昼夜照常推进**，区域外的世界照常运转。玩家在任何情况下都不会被冻住，使用者一旦移动，暂停立即失效。它与原版的 `/tick freeze` 各管各的，**互不干扰**（见 §4.8）。
- **同类魔法体互不攻击。** 没有生命的魔法体随机挑目标时会跳过同类魔法体，也不主动打创造与旁观模式的玩家；只有挨了打才会还手（见 §9.1）。

## §11.4 开服与性能

- **常加载会释放。** 考试或试炼进行中，以奖励箱所在区块为中心的 3×3 共 9 个区块保持强制加载；判定一结束就释放。两人范围重叠时按引用计数算，先结束的那场不会把另一场的加载一起放掉。
- **一场考试占 9 个区块。** 想同时开几场，按「场次 × 9」估区块压力；范围能错开就错开，重叠只是多占加载额度，不加快进度。
- **大范围魔法更吃区块。** 时间暂停最大覆盖 7×7 区块（49 个），空间传送最大 5×5 区块（25 个），启动费按覆盖的区块数累加（见 §4.8）。
- **召唤出来的生物有人收尾。** 考试召唤的生物无论通过、失败还是超时，判定后全部清除，奖励箱保留；服务器启动时还会清扫没有归属的考试实体。
- **人数没有硬性设置。** 模组不含人数上限，能开多少人只看服务端本身。会随人数放大的只有三件事：区块魔力是共账、自然恢复只有每秒 1 点、生物每 3 分钟尝试刷新一次并吃掉 3000 或 5000 点魔力。
- **重启是回魔手段。** 区块魔力不进存档，重进世界或重启服务器一律回满（见 §12.1）。反过来，重启也会打断正在进行的战斗节奏，考试本身不受影响。
